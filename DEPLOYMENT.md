# Deploying DECEPTION

One Render web service serves both the API and the built React site, so there is
no second host, no CORS configuration and no proxy. MongoDB Atlas holds the data.

Everything below is free. Nothing asks for a card.

---

## 1. Before you start

You need two accounts:

| | What for | Free tier |
|---|---|---|
| **MongoDB Atlas** | Stores registrations, payments, tickets | M0, 512 MB |
| **Render** | Runs the app | 750 instance-hours/month |

Atlas must already have:
- A cluster (M0, Mumbai region is closest)
- A database user, and its password
- **Network Access set to `0.0.0.0/0`** — Render's outbound IP is not fixed on
  the free tier, so restricting by IP will simply break the connection. The
  database is still protected by its own username and password.

---

## 2. Create the Render service

1. **render.com** → New → **Web Service** → connect the GitHub repo
2. Render reads `render.yaml` and fills in the runtime, build and start commands
3. Pick the **Free** plan, region **Singapore** (closest free region to India)

If you would rather configure it by hand instead of using the blueprint:

| Setting | Value |
|---|---|
| Runtime | Node |
| Build command | `npm run build` |
| Start command | `npm start` |
| Health check path | `/api/health` |

---

## 3. Environment variables

Render prompts for anything marked `sync: false` in `render.yaml`.

### Required

| Variable | Notes |
|---|---|
| `MONGO_URI` | Full Atlas string, ending in `/deception?retryWrites=true&w=majority`. Without the `/deception` part the app writes to a database called `test`. |
| `ADMIN_PASSWORD` | The Payment Desk login. **Do not** reuse the value from `.env.example` — it is in this repo's public history. |
| `NODE_ENV` | `production` |
| `MOCK_PAYMENT` | `false`. At `true`, anyone can issue themselves a confirmed ticket without paying. |
| `UPI_VPA` | The UPI ID students pay into |

`JWT_SECRET` is generated by Render automatically.

### Fees

| Variable | Default | Notes |
|---|---|---|
| `PER_HEAD_AMOUNT` | `100` | Charged **per participant**. A 5-player squad owes 5x this, a 6-player squad 6x. |
| `CURRENCY` | `INR` | |

This one value drives the expected total, the threshold before a squad can be
approved, and the fee shown on the home page, the rules and the FAQ. Change it
here and restart the service — no rebuild, and nothing to edit in the code.

### Optional

| Variable | Effect if unset |
|---|---|
| `EMAIL_HOST` / `EMAIL_USER` / `EMAIL_PASSWORD` / `EMAIL_FROM` | Emails are recorded but never sent. Nothing breaks: students can still look their ticket up on the Check Status page. Brevo's free tier gives 300/day. |
| `SEED_DEMO_DATA` | Defaults to off, which is what you want. At `true` it loads sample registrations that pollute the dashboard, the exports and the revenue total. |

Never put any of these in the repo. `.env` is gitignored and should stay that way.

---

## 4. After the first deploy

1. Open `https://<your-service>.onrender.com/api/health` — expect
   `{"status":"ok", ..., "env":"production"}`
2. Sign in to **Payment Desk** with `admin@adg.org` and your `ADMIN_PASSWORD`
3. Register a throwaway squad, submit a UTR, tick it, confirm a ticket is issued
4. Delete that test squad's records from Atlas before real registrations open

---

## 5. Keeping it awake (optional)

Render's free tier sleeps a service after 15 minutes of no traffic, and the next
visitor waits roughly 50 seconds while it boots. To avoid that during the
registration window, have something request `/api/health` every 10 minutes —
cron-job.org and UptimeRobot both do this free.

Do not run it around the clock. 24/7 for a month is 744 hours against a 750-hour
budget, which leaves no margin. Roughly 7am–1am is about 558 hours and nobody
registers at 4am.

This is cosmetic: it only affects how fast the first visitor after a quiet spell
sees the page. Data is safe either way, because it lives in Atlas.

---

## 6. Things that will bite you

**Restricting Atlas by IP.** Render's free tier has no fixed outbound address.
The connection will hang and time out rather than fail with a clear message.

**Forgetting the database name.** An Atlas string ending in `/?retryWrites=...`
writes to `test`. It must read `/deception?retryWrites=...`.

**Leaving `MOCK_PAYMENT` at `true`.** The registration form then offers an
instant-pay button that issues a real ticket for no money.

**Changing `PER_HEAD_AMOUNT` without restarting.** The service reads it at boot.

**Special characters in the Atlas password.** Anything with `@ : / ? # & %` must
be URL-encoded or the connection string breaks. Autogenerated passwords are safe.
